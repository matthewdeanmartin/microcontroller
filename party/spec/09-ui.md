# 09 — UI

## Workspace

One Angular 22 workspace in `party/ui/`, built on `miniframework-ng` like Game
Matcher:

| Project | Output | Served by |
|---|---|---|
| `party-core` (library) | models generated from `/api/v1/schema`, view components (event card, RSVP form from modules, group page, calendar list), DSL builder | — |
| `local` | full app | the board (bundled into firmware, gzipped) |
| `companion` | read + DM-send app | GitHub Pages, `party-site` |
| `companion` with `--configuration demo` | demo | GitHub Pages, `party-site/demo/` |

`party-core` components take a `DataSource` interface: `BoardDataSource`
(REST), `SnapshotDataSource` (manifest + decrypt), `DemoDataSource` (bundled).
The RSVP form and the event page are the same components everywhere. Only the
"submit" path differs (REST `PUT`, DM, relay, demo bot).

**The DSL has one grammar and two implementations.** The board parses it in
Rust. The companion site *builds* lines in TypeScript, and the demo bot parses
them in TypeScript. A shared file of test vectors (`spec/dsl-vectors.json`:
input line → parsed command or error) runs in both test suites so they can't
drift.

Budgets: local app initial ≤ 250 KB gzipped, total ≤ 1.2 MB gzipped (the S3 has
room, but every byte is flash and first-load time on HTTP). Routes are lazy.
The companion site has the same budgets.

## Local app screens

- Setup (first admin), sign-in (PIN / Mastodon), sign-up.
- Home: my upcoming events with my answer, invitations, groups' next events.
- Group: about, upcoming, members (by permission), join/leave/request, organizer tools.
- Event: details, modules, RSVP form, who's coming, bring list, ride matches (hosts),
  "answer for…" (household / host), calendar download, change history.
- New/edit event: pick a kind, then modules. Series editor with "this one / following".
- Invitations: create (DM / email / link / QR), list, revoke.
- People and households (search by discoverability, admin edit).
- Me: profile, PIN, linked identities, notification settings, **my personal link (QR)**,
  calendar feed URL.
- Admin: settings, bot, mail, LLM, relay, publication (status, last error, token
  expiry, publish now), delivery queue, inbox log, storage, audit.

## Companion site screens

- Landing: the instance name, public groups, "open my link" if a key is stored,
  freshness banner.
- Group and event pages (public or decrypted), same components.
- RSVP form → preview of the DSL line → send via Mastodon (or relay) → pending badge.
- Invite page (`#/invite/<token>`): what you're invited to (from the public preview
  if any), "accept with Mastodon", or "at the house? open party.local".
- Me (with a key): my answers, my invitations, devices ("forget this device"),
  my Mastodon connection.
- Public Mastodon strip on public groups (bot announcements, group hashtag).
